# Lab 4: File System Extension Report

## 1. 实现说明

本实验在 xv6-riscv 文件系统基础上进行了三项主要扩展：符号链接 (`symlink`)、长文件名支持 (Long Filenames) 以及硬链接 (`link`/`unlink`) 的完善。这些修改在保持原有 xv6 架构的前提下，增强了文件系统的功能和灵活性。

### 1.1 符号链接 (Symbolic Links)

**设计思路**：
引入一种新的 inode 类型 `T_SYMLINK`。符号链接文件本身不存储指向文件的 inode 号，而是存储目标路径的字符串。当 `open()` 系统调用遇到符号链接时，会读取其内容（目标路径），并递归地解析该路径，直到找到最终的非符号链接文件或达到递归深度限制（防止死循环）。

**关键点**：
- **Inode 类型**：在 `kernel/stat.h` 中新增 `T_SYMLINK` (值为 4)。
- **存储**：利用 inode 的数据块存储目标路径字符串。
- **循环检测**：`open()` 解析时设置最大递归深度为 10。
- **O_NOFOLLOW**：支持 `O_NOFOLLOW` 标志，允许打开符号链接本身而不进行跟随。

### 1.2 长文件名支持 (Long Filenames)

**设计思路**：
xv6 原生 `dirent` 结构限制文件名长度为 `DIRSIZ` (14字节)。为了支持更长的文件名（最长 `MAXPATH`），采用了“多槽（Multiple Slots）”方案。

**目录项布局**：
- 如果文件名长度 <= `DIRSIZ`，保持原有布局。
- 如果文件名长度 > `DIRSIZ`，将其拆分为多个片段。
- **续槽 (Continuation Slots)**：前面的目录项用于存储文件名的片段。这些目录项的 `inum` 字段被设为特殊标记 `0xFFFF`，表示该槽位是长文件名的一部分，而非独立文件。
- **主槽 (Main Slot)**：最后一个目录项存储文件名的最后一部分以及真正的 `inum`。

**关键点**：
- **dirlookup**：查找时需要能够识别 `0xFFFF` 标记，拼接连续的续槽内容，直到遇到主槽，再与目标文件名进行完整比对。
- **dirlink**：写入目录项时，如果名字过长，会先寻找足够数量的连续空闲槽位，依次写入文件名片段（设 `inum` 为 `0xFFFF`），最后写入主槽。
- **unlink**：删除长文件名文件时，不仅删除主槽，还会向前回溯并清除所有关联的续槽。

### 1.3 硬链接 (Hard Links)

**设计思路**：
完善标准的 `link(old, new)` 和 `unlink(path)` 语义。硬链接本质上是目录项对同一个 inode 的引用。

**关键点**：
- **link**：解析旧路径获取 inode，增加其 `nlink` 计数，并在新路径目录下创建一个指向该 inode 的新目录项。
- **unlink**：解析路径找到对应的目录项，将其清除（处理长文件名时需清除多槽），并减少 inode 的 `nlink` 计数。只有当 `nlink` 降为 0 且内存引用计数 (`ref`) 也为 0 时，inode 才会真正被释放（由 `iput` 处理）。

### 1.4 Big Write 支持

**设计思路**：
xv6 的日志系统限制了单个事务中能写入的最大块数 (`MAXOPBLOCKS`)。如果用户尝试一次写入大量数据（超过日志缓冲区大小），会导致事务过大而 panic。为了支持大文件写入，`filewrite` 被修改为将一次大的写入请求拆分为多个小的事务。

**关键点**：
- **分块写入**：在 `filewrite` 中引入循环，每次只写入一部分数据（计算出的 `max` 大小），确保每个批次涉及的块数不会超过日志系统的限制。
- **事务管理**：每个分块单独包裹在 `begin_op()` 和 `end_op()` 之间。

## 2. 关键代码修改

### 2.1 kernel/stat.h & kernel/fcntl.h

- `stat.h`: 定义 `T_SYMLINK 4`。
- `fcntl.h`: 定义 `O_NOFOLLOW 0x800`。

### 2.2 kernel/sysfile.c

- **sys_symlink**:
  - 调用 `create(path, T_SYMLINK, ...)` 创建新 inode。
  - 使用 `writei` 将 target 路径写入 inode 数据块。

- **sys_open**:
  - 在 `namei` 解析后，检查 `ip->type == T_SYMLINK`。
  - 如果不是 `O_NOFOLLOW`，则进入循环：
    - 检查深度 `depth < 10`。
    - `readi` 读取符号链接内容（目标路径）。
    - 释放当前 `ip`，调用 `namei` 解析目标路径得到新 `ip`。

- **sys_link**:
  - 增加对 `old` inode 的 `nlink` 计数 (`ip->nlink++`) 并持久化。
  - 调用 `dirlink` 在 `new` 目录下创建目录项。
  - 错误处理：如果 `dirlink` 失败，需回滚 `nlink`。

- **sys_unlink**:
  - 调用 `dirlookup` 找到目录项及其偏移量 `off`。
  - 检查目录是否为空（如果是目录）。
  - 清除目录项：不仅清除主槽，还通过循环清除之前的所有续槽 (`inum == 0xFFFF`)。
  - 减少 inode 的 `nlink`。

### 2.3 kernel/fs.c

- **dirlookup**:
  - 增加逻辑处理 `de.inum == 0xFFFF`。
  - 使用 `lpos` 缓冲区累积长文件名片段。
  - 当遇到主槽时，将累积的完整文件名与目标 `name` 进行比较。

- **dirlink**:
  - 判断名字长度。若 `> DIRSIZ`，计算所需槽位数 `need`。
  - 遍历目录寻找连续 `need` 个空闲槽位。
  - 依次写入续槽（`inum=0xFFFF`）和主槽。

- **namecmp**:
  - 修改比较逻辑，不再受限于 `DIRSIZ`，而是比较直到字符串结束或达到 `MAXPATH`。

### 2.4 kernel/file.c

- **filewrite**:
  - 计算单次最大写入量 `max = ((MAXOPBLOCKS-1-1-2) / 2) * BSIZE`。
  - 使用 `while` 循环处理写入：
    - 每次处理 `n1 = min(n - i, max)` 字节。
    - 在循环体内调用 `begin_op()` -> `ilock()` -> `writei()` -> `iunlock()` -> `end_op()`。
    - 更新偏移量和剩余字节数。

## 3. 验证与测试

编写了三个特定的测试程序来验证实现的正确性：

### 3.1 symlinktest.c
- **基本功能**：创建符号链接并成功跟随读取目标文件内容。
- **目录链接**：验证符号链接可以指向目录，并能通过 `chdir` 进入。
- **O_NOFOLLOW**：验证设置该标志时 `open` 打开的是链接本身而非目标。
- **死循环检测**：创建循环引用的符号链接（a->b->a），验证系统能否正确报错并停止。

### 3.2 longnametest.c
- **超长文件名**：创建长度超过 `DIRSIZ` (如 20-100 字符) 的文件，验证 `open`、`write`、`read` 正常。
- **混合环境**：在同一目录下混合创建短名和长名文件，验证 `ls` 和查找互不干扰。
- **Unlink 清理**：删除长名文件后，检查目录中不再残留任何相关的续槽（通过再次创建同名文件验证）。

### 3.3 hardlinktest.c
- **引用计数**：创建硬链接后，验证 `stat` 返回的 `nlink` 数增加。
- **数据共享**：通过一个链接写入，通过另一个链接读取，验证内容一致。
- **Unlink 语义**：
  - 打开文件获得 fd。
  - `unlink` 删除文件名。
  - 验证通过 fd 仍能读写文件（inode 未释放）。
  - `close(fd)` 后，验证空间被释放。

### 3.4 bigwrite.c
- **大文件写入**：尝试写入远超日志缓冲区大小的数据（如 3000 次 1024 字节写入）。
- **事务拆分验证**：如果内核未正确拆分大写入为小事务，该测试将触发 panic 或写入失败。成功运行表明 `filewrite` 中的分块逻辑工作正常。

所有测试均通过，证明了 inode/dirent 扩展方案及系统调用实现的正确性和鲁棒性。
